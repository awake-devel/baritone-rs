# Injected errors (see mutate.py) that the L2 comparison does not catch, and why.
# Format: <mutation name> | <class>: <reason>
# class is "no effect" (the error cannot change any answer of the comparison) or "hole" (a real gap in the test, left open on purpose).
# The gate fails on a missed mutation that is not listed here. Each reason was read from the engine and upstream source after the
# corpus had been strengthened where that was cheap (the Rust-only property checks in src/main.rs were added for that: single use,
# cancel flag, post processing twice, static cutoff without a goal). "Unit tests catch it" means the run of `cargo test -p baritone-engine`
# fails on the mutant; mutate.py does not count that as caught. Order: the old entries first, then the new ones in the order of mutate.py.
inverse coefficients a little off | no effect: every comparison against bestHeuristicSoFar has a margin of MIN_IMPROVEMENT (0.01); a relative change of 1e-7 of the cost only matters for an exact tie at that margin, which no generated search reaches
start node: combined cost 0 | no effect: the start node is alone in the open set when it is taken out, so its key orders nothing, and no later code reads the combined cost of a node that was taken out
node cost starts below infinity | no effect: a node's cost starts at COST_INF only to lose against any real cost; 999999 loses the same way unless a path costs about a million ticks, and the first cost is never printed
favoring: coefficient 1 not skipped | no effect: with a coefficient of 1 the map is not empty, but every entry is 1.0 and multiplies a cost by 1.0, so costs, order and paths are the same; only Favoring.isEmpty differs and nothing outside the search reads it (a unit test catches it)
avoidance: spawners with coefficient 1 | no effect: same for the avoidance spheres, they multiply by 1.0 (a unit test catches it)
static cutoff: goal check needs a longer path | no effect: at a length of exactly pathCutoffMinimumLength the cut keeps min - 1 as the last index, which is the whole path, so cutting and not cutting give the same path
heap: removed slot not cleared | no effect: the array slot above the size is only read again after an insert has written to it
heap: single element early return | hole: without the early return the last node taken out is written back to slot 1 with a stale heap position; that only matters when a node that was already taken out gets a cheaper cost later, which needs an inconsistent heuristic, and no generated search has one (a unit test catches it)
heap: right child read past the end | no effect: the slot past the end holds the key of the element being sifted down, so the right child is chosen only when that key is smaller than the left one, and the loop then stops on it at once, where it stopped before
heap: right child without size check | no effect: the same, the loop never has a child past the end to look at
cell key: x mask short | no effect: two nodes of one search would need x columns 2^32 blocks apart to share a cell, and the world border is 30 million blocks
cell key: z mask short | no effect: the same for z
